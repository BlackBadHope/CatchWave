# Local LAN diagnostics

Android and the compatible Windows Host retain the latest 256 events in a local ring, at most 128 KiB per file plus a bounded temporary snapshot. Android: private app files; Windows: local application data/CatchWave/diagnostics.log. Both offer view and explicit export through a native file picker. No audio or raw sensor data is recorded; no automatic upload exists. Wall-clock ISO timestamps include UTC/offset and a timezone, while deadlines/freshness use monotonic clocks. New connection attempts receive new nonsecret IDs; after FORMAT both journals use the protocol's nonsecret random session ID. These IDs are correlation metadata, not pairing credentials.

Android events: SESSION/RECONNECT/STAGE/STOP, FOCUS (gain/duck/loss), ROUTE (numeric AudioDeviceInfo type only), ARMING (locked/button armed/manual off/neutral refresh/sensor fault), CONTROL (phone and PC permissions/epochs and readiness changes), GESTURE, VOLUME and ACK. A snapshot every two seconds uses v0..v9: received frames, played frames, last sequence, audio age ms, queue drops, underruns, route type, media volume, AudioTrack play state, output classification (1 zero PCM, 2 nonzero PCM), total late drops and last network-read excess age ms (v10/v11). Service dumps split lateReadDrops/latePlaybackDrops and report clockCorrectionMs/playbackResyncs. VOLUME uses v0 before/v1 after/v2 owned mute checkpoint/v3 changed. CONTROL PERMISSION_CHANGE uses v0 phone allowed/v1 PC allowed/v2 phone epoch/v3 PC generation. CONTROL readiness codes NO_PERMISSION/NO_SENSORS/NOT_ARMED/NEUTRAL_WAIT/READY log only transitions, with v0 armed (0/1) and v1 neutral remaining ms. DISPLAY_NEUTRAL preserves activation and invalidates queued commands. EXPLICIT_ACTIVATION records the button action; service dumps report armingMode=BUTTON and manualActivationReady. TONE_FAILED is nonfatal and stores no exception text. GESTURE BLOCKED uses an action ordinal; accepted requests use its fixed action name. ACK confirms Host dispatch, not audible player success.

Windows SNAPSHOT uses v0 frames sent/v1 skipped intervals/v2 last sequence/v3 client output state/v4 client-report age ms. CAPTURE uses v0 cumulative WASAPI packets/v1 silent packets/v2 bytes consumed for this frame. NO_CAPTURE_PACKET means the source provided no captured bytes and the Host filled silence; SILENT_CAPTURE means captured zero samples. ROUTE DEFAULT_CHANGED means the current default differs from the endpoint opened for this session; it does not switch endpoints. CONTROL ACCEPTED/REJECTED uses v0 action/v1 command sequence. STOP reports fixed codes, without exception text.

Fresh received/played frames with nonzero PCM, positive media volume and a confirmed route mean AudioTrack accepted data; they do not prove sound reached the listener. SILENT_SOURCE differs from STOPPED_STREAM; focus loss, unknown route and zero volume have explicit classifications. A gesture MUTE/VOLUME event can establish local software changes; an externally changed volume alone cannot identify who caused it. Windows cannot directly observe Android audio focus or its physical speaker.

Android 0.1.40 adds PHONE_AUDIO stage/snapshots for preserved connections paused behind phone audio. FOCUS PHONE_AUDIO_PAUSED/PC_AUDIO_RESUMED record focus changes; RETURN_REQUESTED/RETURN_DELAYED identify automatic recovery requests. Service dumps report focusPaused and focusDroppedFrames. Frames continue to arrive during the pause but are not replayed later. STOP AUDIO_FOCUS_LOST is no longer the normal response to another app starting audio. Manual disconnect closes the focus observer and invalidates delayed recovery callbacks. A concurrent newer frame arrival is fresh even when it was published just after the health check captured its monotonic timestamp.

Persistence runs about once per second off audio/sensor threads. Write/clock failures retain usable RAM events and increment a diagnostic failure count; abrupt termination can lose the last second. Old history is merged before current startup events. Repeated updates overwrite the bounded snapshot. No endpoints, device names/IDs, IPs, QR, authentication token, certificate pin, signing key, private messages, track names or audio bytes are logged.

The earlier owner report of lost sound has snapshots showing a live Host/TCP, fresh nonzero PCM accepted by AudioTrack, no underruns, positive volume and no mute command. There was no historical focus/route journal then, so a root cause is not established. A Defender block during APK output copying was observed separately; it is not evidence of an audio failure.

0.1.45 adds PC_AUDIO_DUCKED for an explicit duck callback and focusDucked in service dumps. Android native automatic ducking may deliver no callback, so this flag is not a measurement of notification attenuation. USB_AUTO_SAVE_FAILED records a failed optional auto-route preference save; no hardware identity is logged.
