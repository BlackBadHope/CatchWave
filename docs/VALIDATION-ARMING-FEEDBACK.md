# Validation: arming integration and sound feedback

Android 0.1.22-arming-feedback/versionCode 29 fixes conditional failures introduced with the timed arming gate: display rotation cleared gyro/acceleration dependencies and could immediately close a valid window; orientation activity recreation could discard the sensor session; comparing the first acceleration sample to the processing-time reset could erase fresh neutral on ordinary delivery latency. Display changes now reset neutral and invalidate queued commands while preserving physical sensor samples and the original deadline. Initial missing sensor dependencies wait; genuinely stale, unreliable or invalid sensors still close the window. The compatible Windows Host remains 0.1.21-armed-diagnostics; no Host restart or protocol change is necessary.

The permission switch, timed active window and neutral readiness are shown separately, with fixed reason codes. An optional quiet 120 ms mono frequency sweep rises on actual opening and falls on actual closure. It uses the current Android media output/volume, takes no audio focus and changes no system volume or route. At media volume zero it is inaudible. Neutral/display revisions and permission alone do not create sounds. Existing haptics remain. The reset button explicitly closes activation; stable nearly horizontal face-up still closes it even in the hand.

Regression checks exercise the real service sensor callbacks with different sensor ordering and nonzero delivery latency, rotation/neutral/deadline/queued authority, three taps reaching the fake control queue, upright pickup, face-up closure, expiry, real gaps/accuracy loss and permission revocation. Tone tests check actual edges, mute/unmute behavior and bounded waveform amplitude/duration. Automated tests use fake sensors, transport and volume; no real audio capture or media-key dispatch occurs.

Local final release checks: **277 tests, 0 failures; lint 0 errors/19 warnings** (the additional warning concerns hard-coded UI text localization). The higher-code rollback passed **240 tests, 0 failures; lint 0 errors/18 warnings**. Independent review accepted the corrected source after both identified issues were resolved. GitHub Actions repeats Android, Windows self-tests and Java/.NET protocol checks on publication. An unmodified older service is tested with the new regression cases to distinguish a reproduced code defect from a theory. These software checks do not prove which path occurred in the owner's failed physical attempt: the Android ring was unavailable while USB/ADB was offline. The preserved Windows ring contained live capture/output snapshots and no control execution events.

Installation requires owner acceptance of the native prompt and exact package/version/signer/hash readback. A higher-code rollback returns the previously accepted version-25 runtime, including its continuously enabled gesture behavior; disable management outside deliberate testing. No pairing preference extraction, automatic grants, security changes, synthetic device gestures or agent-triggered player actions are used. Physical activation/tone/neutral/action acceptance, accidental-input rate and screen-off/battery behavior remain open until tested by the owner.
